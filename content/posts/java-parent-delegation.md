如果没有系统学习过 JVM，“双亲委派”可能是一个陌生的名词。它是 Java 类加载器体系中的核心机制，负责在加载类时建立稳定的优先级和隔离边界。

## 什么是双亲委派机制

当一个类加载器收到加载某个类的请求时，它不会立即自己查找，而是先把请求委托给父类加载器。父类加载器继续向上委托，直到最顶层的引导类加载器。

只有当父类加载器无法完成加载时，当前类加载器才会尝试在自己的搜索范围内加载这个类。也就是说，流程是“先向上委托，再逐级回退”，并不是简单地由父类直接替子类完成所有加载。

## 类加载器层次

传统 JDK 版本中，常见的类加载器包括：

- **引导类加载器（Bootstrap ClassLoader）**：由 JVM 使用底层语言实现，负责加载 Java 核心类；
- **扩展类加载器（Extension ClassLoader）**：加载 JRE 扩展目录中的类库；
- **应用类加载器（Application ClassLoader）**：加载 classpath 或模块路径中的应用类，是普通 Java 程序默认使用的类加载器；
- **自定义类加载器（Custom ClassLoader）**：根据业务需要从指定目录、网络或加密数据中加载类。

JDK 9 之后，扩展类加载器更名为**平台类加载器（Platform ClassLoader）**，Java 核心类也不再以传统 `rt.jar` 的形式组织。因此，`rt.jar` 和 `%JRE_HOME%/lib/ext` 主要是旧 JDK 时代的描述，分析现代 Java 程序时应以模块系统和实际运行时版本为准。

## 工作流程示例

假设应用类加载器需要加载 `com.example.User`：

1. 应用类加载器先把请求委托给父类加载器；
2. 父类加载器继续委托给引导类加载器；
3. 引导类加载器检查自己的核心类加载范围，发现没有 `com.example.User`，返回无法加载；
4. 父类加载器继续检查自己的范围，仍然无法找到该类；
5. 应用类加载器最后在 classpath 中找到 `com.example.User` 并完成定义。

如果请求的是 `java.lang.String`，引导类加载器会优先加载 JDK 提供的核心类，后续类加载器不会再加载应用目录中同名的自定义类。

## 为什么需要双亲委派

### 避免重复加载

父类加载器已经加载过的类，子类加载器无需重复定义，可以减少重复加载和类对象分裂。需要注意，Java 中一个类的唯一身份由“全限定类名 + 定义它的类加载器”共同决定。

### 保护核心类

如果没有父优先机制，应用就可能尝试定义一个名为 `java.lang.String` 的类来替换核心类。双亲委派让核心类优先由引导类加载器加载，降低恶意覆盖和类型混淆的风险。

### 统一加载规则

所有遵循标准委派模型的类加载器都使用一致的查找顺序，避免同名类在不同路径被随意加载，提升运行时行为的可预测性。

## 打破双亲委派的场景

双亲委派是默认策略，但并不是不能改变。某些框架和机制需要让子类加载器或线程上下文类加载器参与查找。

### SPI 与线程上下文类加载器

以 JDBC 为例，`java.sql.DriverManager` 属于 JDK 平台类，但具体数据库驱动通常位于应用 classpath。平台类需要反过来发现应用提供的实现，因此会使用线程上下文类加载器等机制完成服务发现。

### Tomcat 等容器的类隔离

Tomcat 中不同 Web 应用可能依赖同一个类库的不同版本。容器通常为每个应用创建独立的类加载器，并对应用类采用更灵活的加载顺序，从而避免不同应用之间发生依赖冲突。

### 模块化、插件化和热部署

插件系统、脚本引擎和热部署框架也可能使用自定义类加载器，让模块拥有独立的类路径和生命周期。卸载模块时，只要对应类加载器及其加载的类不再被引用，就有机会被垃圾回收。

## 常见排查方法

可以打印一个类实际使用的类加载器：

```java
System.out.println(String.class.getClassLoader());
System.out.println(MyApplication.class.getClassLoader());
```

`String.class.getClassLoader()` 在很多 JDK 中会输出 `null`，这通常表示它由引导类加载器加载，而不是表示没有类加载器。

如果遇到 `ClassNotFoundException`、`NoClassDefFoundError` 或同名类类型转换异常，应重点检查：

- 类是否真的位于目标 classpath 或模块路径；
- 加载类的类加载器是否正确；
- 是否存在多个版本的同名依赖；
- 容器或插件是否创建了独立的类加载器；
- 线程上下文类加载器是否被错误修改。

## 总结

双亲委派机制可以理解为“先逐层上报，父类无法处理时再由子类接手”。它通过父优先保证核心类的唯一性和安全性，同时减少重复加载和类型冲突。

SPI、Tomcat 类隔离、插件化和热部署等场景会有意调整默认委派策略。理解“类名 + 类加载器”共同决定类型身份，是排查 Java 类加载问题的关键。
